# 聚合pay V2 支付验收

> 目标：先用普通用户的 7% 支付宝通道验证支付创建、RSA 验签、异步回调、
> 订单履约、Aisou 采购、交付和代理净利润；验证通过且 T+1 实际结算一致后，
> 再由所有者购买 ¥288 超级会员并把渠道费率改为 4%。

## 上线边界

- 开通会员、支付测试单和真实上游采购都属于真实资金动作，由所有者亲自完成。
- 商户私钥不得粘贴到聊天、工单、仓库、日志或截图；只通过 Agent Switch
  写入生产配置。
- 代码、合成测试或创建出二维码都不等于验收成功。必须保留支付请求、网关响应、
  回调、订单、采购、交付、利润账本和 T+1 结算八段证据。

RSA 密钥对后，只保存商户私钥和平台公钥；任何渠道更新都必须重新执行只读配置校验。

## 托管子站手续费规则

托管子站始终让客户支付代理设置的展示售价，不在结账页额外加小数手续费。

```text
商品差价 = 子站售价 - 平台供货价
支付手续费 = 子站售价 * 渠道费率 + 固定手续费
代理最终利润 = 商品差价 - 支付手续费
```

例如供货价 ¥100、子站售价 ¥150、费率 4%：手续费 ¥6，代理最终利润 ¥44。
若手续费大于商品差价，差额必须在创建支付单时从代理预充值采购钱包原子暂扣；
余额足够才允许创建支付单，余额不足仍拒绝。支付成功后暂扣转为实际支出，支付创建失败、
失败回调、过期回调或订单过期/取消时必须幂等退回。主站订单仍遵循主站全局手续费策略；
余额 API 订单没有终端客户支付手续费。

## 普通用户 7% 验收

1. 新建一个独立的、仅验收子站可见的 `epay/alipay` 渠道，先填 `7.00%`，
   不替换现有 ZPay 渠道。
2. 将该渠道只分配给验收子站；确认主站和其他子站不可见。
3. 创建一笔代理差价足以覆盖 7% 的最小真实商品订单。
4. 在付款前导出一次 trace；由所有者亲自扫码付款。
5. 回调必须同时通过 RSA 签名、商户 ID、订单号、金额、币种和成功状态校验，
   HTTP 响应必须为 `success`。
6. 支付成功后检查：订单已支付、只创建一次 Aisou 采购、交付仅一次、下游回调
   幂等、代理利润为“商品差价 - 7%手续费”且先处于待确认。
7. 若异步回调缺失，使用 V2 `/api/pay/query` 的签名主动查询修复；不得换订单号
   重复采购。
8. 次日核对真实结算金额、实际费率和打款主体；未到账前不得将代理利润置为可提现。

证据导出：

```bash
./scripts/export-integration-trace.sh <业务订单号> <网关订单号>
```

## 升级 4% 后

1. 所有者亲自购买 ¥288 超级会员。
2. 从商户后台重新读取实际支付宝费率，确认确为 4%，再把渠道费率更新为 `4.00`。
3. 重复一笔最小支付验收，不能只改数据库费率。
4. 验证新支付快照为 4%，旧订单仍保持创建时的 7%快照。
5. 连续观察至少一个完整结算周期后，才允许把新渠道扩大到更多托管子站。

## 尚未证明的事项

- “没有日/月限额”尚无书面证据；平台协议允许动态限额和延迟结算。
- 退款是否返还原支付手续费、保证金和冻结规则尚未通过真实账单验证。
- 普通用户测试成功只证明当时这一个商户号、商品和金额可用，不证明长期无限额。
